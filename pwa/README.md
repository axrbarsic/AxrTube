## Версия 35: встроенный тест привязки Lock Screen

Настройки → «Тест экрана блокировки» → «Открыть встроенный тест» открывает
`/system-player` в той же PWA, с тем же манифестом, без новой установки.
Контрольный MP3 воспроизводится нативным audio element без YouTube, HLS.js,
engine/app bootstrap, MediaSession/AudioSession writes и восстановления пауз.
Страница предупреждает, если открыта обычной вкладкой вместо PWA.

Оба режима сохраняют локальный ограниченный журнал: до 4 запусков, до 240
событий на запуск. Pageshow/pagehide, persisted, focus/blur, visibility, media
events и редкий прогресс переживают перезапуск, если localStorage доступен.
Сохранение работает только в пределах того же хранилища PWA. При запрете
хранилища текущие события остаются доступны для скачивания в памяти.
Контрольный отчёт включает ручную отметку «Открылся чужой ярлык»; имя приложения,
владелец системного Now Playing и внутренние процессы iOS странице недоступны.
Журнал не содержит cookies, токенов, query string, media URL или названий видео
и никуда автоматически не отправляется. Основной отчёт плеера тоже включает
сохранённую историю. Открытие теста останавливает текущий ролик с подтверждением.
Это диагностика, не заявленное исправление подмены ярлыка. Авторизация и политика
фонового воспроизведения в этом checkpoint не менялись.

## Версия 34: проверка регрессии привязки iOS PWA

## Версия 33: двойная пауза при сворачивании Android

Отчёт v32 подтвердил успешный MSE-запуск на Android Chrome 155. При переходе
в hidden первая пауза автоматически восстановилась, но через 31 мс пришла

Последовательность отчёта воспроизведена адресным тестом, проверка обновления

## Версия 32: смешанный отказ получения потока

Отчёт v31 остановился до подготовки плеера: сервер вернул `NO_HLS` и

## Версия 31: прерывание запуска на Android

Отчёт Android Chrome 155 из установленной PWA показал `source-ready`, затем
Pause/ошибку запуска при readyState=0 и только после этого loadedmetadata.
Вне Apple теперь предпочтителен MSE/HLS.js при его поддержке, до Play ожидаются
метаданные, а не скачивание ролика. Нативная ветка Apple остаётся прежней.
Одиночный AbortError допускает одну повторную попытку на том же источнике,
но не после явной паузы, закрытия, смены запуска или ухода в фон.
Обработчик ошибки больше сам не вызывает Pause. Отчёт включает transport и
этапы ожидания метаданных. Модельные проверки этих переходов зелёные;
физическое подтверждение исправления Android ещё требуется.

## Версия 30: единый вход и автопродление Google

Один Google-вход запрашивает права для профиля, подписок и рекомендаций вместе,
а также offline access для продления сессии без повторного окна входа. Полные
YouTube-права технически разрешают управление аккаунтом, код использует их
только для чтения. Явный readonly-вариант остаётся доступен через `?readonly=1`.

Короткий access token отделён от зашифрованного refresh token. Оба передаются
только в Secure/HttpOnly/SameSite cookies, не в JS/localStorage или JSON. При
истечении access token сервер получает новый; временная сеть/ошибка Google не
считается выходом. Отмена входа сохраняет прежнюю сессию; успешная смена аккаунта
и выход меняют binding, старые credentials больше не подходят.

Локальный предел сохранения составляет 180 дней, либо меньший срок, который
вернул Google. Это не обещание бессрочного доступа: в Google Cloud Testing
refresh token обычно истекает через 7 дней. Отзыв разрешений, удаление cookies
и отдельное хранилище Safari/PWA также могут потребовать повторного входа.
Старым сессиям без refresh token нужен один переход «Сохранить вход Google».
Плеер, фон и блокировка рекламы в этом checkpoint не изменены.

## Версия 29: запуск HLS в Chromium

В MSE-ветке плеер ждёт `MANIFEST_PARSED` до вызова Play. Закрытие плеера
отменяет ожидание, фатальная ошибка или таймаут освобождают блокировку запуска.
Нативная HLS-ветка Safari не изменена. HLS.js фиксированной версии загружается
через собственный `/hls.js` с резервным источником пакета. В Chromium ошибка
загрузки библиотеки больше не игнорируется. Проверены обе ветки video/audio
с MSE-моделью, реальная проверка Android остаётся за пользователем.

Вход пока по-прежнему ограничен одним часом без refresh token. Его cookies
имеют явный Max-Age, немедленный выход после перезапуска отдельно не подтверждён.

## Версия 26: отдельное разрешение для проверки рекомендаций

В профиле добавлена отдельная проверка с расширенным OAuth scope `youtube`.
Google технически разрешает управление аккаунтом; приложение использует доступ
только для чтения. Обычный вход остаётся `youtube.readonly`. Отказ при расширении
не удаляет текущую сессию. Токен хранится только в зашифрованной HttpOnly cookie
не более часа, refresh token не сохраняется. Совместимость персональной главной
ещё требует живой проверки, главная пока не переключена на непроверенный источник.

Live-проверка с реальным Google Web OAuth входом успешна для `/api/account`,

## Версия 24: проверка источника персональной главной

Добавлен серверный `/api/account/home`: тот же TVHTML5/FEwhat_to_watch browse,
что у нативного AxrTube. Только существующая encrypted Google-сессия, Bearer
не возвращается JS, фиксированный youtubei.googleapis.com, no-store/manual
redirect, лимит ответа 8 MB. Возвращаются порядок YouTube, continuation и
visitor для следующей страницы. TV video/reel tiles распознаются отдельно,
не-видео и рекламные tiles отбрасываются. Ошибки типа входа и logged-out
ответы не выдаются за персональные рекомендации.

Это проверочный checkpoint: главная пока не переключена до live-проверки
совместимости собственного Web OAuth-токена с TV browse. Успешные mock-тесты
не считаются доказательством доступности персональной ленты пользователя.
Клиент Google, scopes, время сессии и медиадвижок не менялись.

## Версия 23: полная стенограмма

Перенесён основной сценарий `PlayerTranscriptPanel` из iOS: отдельная панель
«Стенограмма», весь текст разделами, оглавление, «Копировать всё», статус
«Скопировано» и сохранение Markdown. Открывается из плеера или меню карточки,
в том числе без начала воспроизведения. Закрытие панели не останавливает звук.
Копируется весь готовый документ с названием, каналом, ссылкой, языком,
длительностью, датой, оглавлением и текстом всех разделов, не только видимый экран.

Основа переноса: `TranscriptBookPolicy` (разделы по 5 минут, абзацы с порогами
35/75/120 слов, устранение roll-up повторов до 32 слов), WebVTT-путь субтитров.
`GET /api/transcript?id=...&lang=...` читает публичную дорожку YouTube, без
OAuth/Google cookies, рекламного iframe, скачивания медиаролика или Mac-туннеля.
Служебные URLs субтитров не возвращаются клиенту. Разрешены только точные
HTTPS timedtext-хосты/пути и совпадающий video ID; redirects не следуются.
Лимит дорожки 8 MB: превышение является ошибкой, не усечённой «полной» стенограммой.
UI различает отсутствие дорожки и сбой получения. Буфер обмена вызывается из
нажатия кнопки уже после загрузки; при отказе браузера доступен полный выделяемый
текст для ручного копирования. В памяти сохраняются максимум два документа.

Честная граница parity: встроенный Apple Translation из iOS не доступен в PWA.
Здесь выводится исходная доступная дорожка, приоритет языка UI, затем ru/en,
ручная раньше автоматической. Наличие русской дорожки не гарантируется, ролики
без доступных субтитров не получают выдуманный текст. Весь UI панели переведён
на шесть уже поддерживаемых языков, сам текст видео не машинно переводится.

Адресные проверки: `node scripts/test-transcript.mjs`, i18n/catalog/account и
существующие player/update tests. Локальная live-проверка asQM5v36J30 получила
русскую дорожку, 7 разделов / 40 абзацев. Она не является iPhone-приёмкой.

## Версия 21: Shorts, закрепления и установленное PWA

- Настройки -> «Скрывать Shorts». По умолчанию выключено, выбор сохраняется
  вместе с прежней локальной медиатекой. Вкладка Shorts скрывается, её прямой
  hash возвращает на главную. Распознанные Shorts убираются из карточек,
  очереди и автопродолжения, но сами записи не удаляются.
- У авторизованной главной при скрытии Shorts источник меняется с uploads на
  публичную вкладку «Видео» каналов. Без передачи OAuth в InnerTube, без
  эвристики «любой короткий ролик = Shorts». Порядок в этом режиме: группы
  каналов по алфавиту, порядок роликов из вкладки канала. Плейлисты Data API
  не дают надёжной метки Shorts, некоторые Shorts там могут остаться.
- Существующий раздел «Подписки» автоматически загружает страницы по 50,
  максимум 150 страниц, и показывает прогресс/ошибки. Повторяющиеся page token
  останавливают загрузку. Локальные каналы продолжают работать без Google.
  Звезда закрепляет канал наверху, повторное нажатие открепляет. Закреплённые
  идут в порядке закрепления (новые выше), остальные по алфавиту. Выбор локальный,
  серверные подписки YouTube не меняются, новый раздел не создаётся.
- Только в display-mode standalone / iOS navigator.standalone: viewport без
  масштабирования, блокировка page-pinch и CSS touch-action/overscroll без
  браузерного растягивания страницы. Обычная вкладка, прокрутка одним пальцем,
  поля ввода, выделение текста и нативные fullscreen controls не отключаются.
  iOS может резервировать системные жесты; физическая приёмка на iPhone нужна.

Тесты: `test-preferences.mjs`, `test-account-feed.mjs`, `test-account.mjs`,
`test-catalog.mjs`, `test-updates.mjs`. Медиадвижок и SponsorBlock не изменены.
Справка оригинала: [Show fewer Shorts](https://support.google.com/youtube/answer/6342839?co=GENIE.Platform%3DiOS&hl=en).
Полный off и локальное закрепление являются функциями AxrTube, а не заявленным
копированием недокументированных возможностей оригинального iOS-приложения.

## Версия 20: главная после Google-входа

Исправлена продуктовая недоработка: в v18/v19 главная всегда запрашивала
гостевой каталог, независимо от Google-сессии. Теперь она сначала проверяет
аккаунт, показывает его имя и загружает видео из подписок. В настройках тоже
видны статус и переход к профилю. При возврате в приложение проверка аккаунта
повторяется не чаще раза в минуту; плеер не перезапускается.

Лента читает подписки по алфавиту порциями по 6 каналов, по 5 последних видео
из uploads-плейлиста каждого. Загруженные ролики объединяются без дублей и
сортируются по дате публикации. Следующие каналы загружаются кнопкой. Это не
всеобщая хронологическая лента до загрузки всех каналов и не персональные
рекомендации главной YouTube. Истёкший вход и ошибки не маскируются гостевой
лентой. Ответы приватные/no-store, токены не раскрываются клиенту.

Основа: [uploads playlists](https://developers.google.com/youtube/data/guides/implementation/videos).
Параметр [activities.home](https://developers.google.com/youtube/data/reference/rest/v3/activities/list)
deprecated и не возвращает персональную главную.
Адресные тесты: `node scripts/test-account-feed.mjs`, `test-account.mjs`,
`test-catalog.mjs`, `test-updates.mjs`. Реальные подписки и iPhone standalone
проверяет владелец после публикации; синтетические тесты их не подтверждают.

## Версия 19: исправление запуска Google-входа

У HTML-оболочки политика Referrer-Policy изменена с `no-referrer` на
`same-origin`: браузер может передать настоящий Origin при отправке формы
входа внутри сайта, не раскрывая referrer внешним адресам. OAuth callback
сохраняет `no-referrer`. Проверки Origin/state/PKCE не ослаблены; запросы
с отсутствующим, чужим или `null` Origin по-прежнему отклоняются.
Реальный Google consent/callback на iPhone пока требует проверки владельца.
Плеер и фоновое восстановление не менялись.

## Версия 18: подключение YouTube

Создан собственный Web OAuth client в отдельном проекте Google. После явных
подтверждений владельца приняты политики, включён YouTube Data API v3 и добавлен
тестовый пользователь. Ключи сохранены только в защищённых runtime-настройках
Sites. В source, manifest и JS клиента реальных значений нет.

Вкладка «Вы» открывает стандартный Google authorization-code redirect с PKCE
и scope `youtube.readonly`. Подписки и плейлисты читаются отдельными серверными
GET-маршрутами, аккаунт не изменяется. Sites identity и его callback не заменяются.
Callback `/oauth/google/callback` проверяет state и привязку к браузеру.
Access token хранится в AES-GCM encrypted Secure/HttpOnly/SameSite=Lax cookie,
не в localStorage/IndexedDB/отчётах и не возвращается JS. Logout меняет epoch,
чтобы запоздалый callback не восстановил вход в обычном браузере после выхода.

Границы первого slice: соединение действует максимум час, refresh token не
сохраняется, после истечения нужен повторный вход. Выход относится к этому
браузеру, не отзывает Google grant на других устройствах. Google project пока
в Testing, общий публичный вход и verification ещё не готовы. iPhone standalone,
перенос сессии между внешним Safari и PWA, реальный callback и чтение личной
медиатеки требуют физической проверки владельца. Вход не подставляет OAuth
token в анонимный медиарезолвер и не снимает его LOGIN_REQUIRED/403.

Проверки: `node scripts/test-account.mjs`, прежние player/catalog/background/
updates tests. Независимый security review не завершился из-за лимита сессии,
поэтому его успешное прохождение не заявляется. Полный end-to-end вход пока
не принят. Техническая основа: [Google web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server).

Версия 17: Alex принял продолжение в фоне v16. Короткая пауза при сворачивании
остаётся допустимой; механизм фонового восстановления не менялся.

Основная оболочка теперь проверяет `/api/version` при открытии, pageshow из
bfcache и возвращении в foreground. SW проверяется с updateViaCache=none.
JS/CSS закреплены за release, несовпадение возвращает 409. При старом документе
до запуска приложения выполняется один guarded reload. Пока загружен медиапоток,
обновление откладывается до закрытия плеера и не обрывает фон. Не удаляются
IndexedDB, история и сохранённые медиа; чистятся только прежние shell caches.
При отсутствии сети открывается сохранённая оболочка с явным предупреждением.
Гарантировать свежую версию без сети или до окончания rollout хостинга невозможно.
Статус обновления виден в настройках.

Google-вход: создан отдельный проект, настройка бренда остановлена до принятия
владельцем Google API Services User Data Policy. OAuth-клиент ещё не создан.
Native iOS использует реквизиты Google TV, извлекаемые из TV JS, не собственный
Web client проекта. Их перенос в публичный PWA не выполнялся. Следующий шаг:
собственный Web OAuth, официальный authorization-code flow, YouTube read-only
scope, секреты только в runtime хостинга. Доступ к аккаунту ещё не реализован.

Версия 16: отчёт v15 показал pause при visibility=visible за 139 и 171 ms
до hidden. Старый обработчик отменял intent и не пытался продолжить поток.
Теперь неотмеченная вводом пауза сохраняется как кандидат на 400 ms, без
таймера. Только следующий hidden в этом окне вызывает один play того же media
element. App/Lock Screen Pause, наблюдаемый pointer/touch/key ввод в controls,
reset и interrupted отменяют кандидата. Обычная пауза без hidden не возобновляется.
Native pause без доступного input-события в те же 400 ms неотличима от системной,
это ограничение эвристики. В отчёте появились pause-pending/pause-before-hidden.
Обе измеренные последовательности покрыты unit-тестами; iPhone-приёмка впереди.

Версия 15: для сообщения о паузе при сворачивании добавлен явный
`navigator.audioSession.type='playback'` по доступности API. Общий движок
запоминает намерение воспроизводить и делает одну попытку `play()` того же
элемента, только если он играл перед переходом hidden и остановился в первые
2 секунды. Источник, позиция и режим не переключаются. Нет keepalive-таймеров.
Ручная пауза, remote Pause, reset/close, ended/error и известное interrupted
состояние отменяют восстановление. На возврате в foreground автозапуска нет.
Report v15 содержит состояние Audio Session и события перехода/восстановления.
Адресные тесты `node scripts/test-background.mjs` проходят; физическая приёмка
сворачивания на iPhone ожидается. Это кандидат исправления, не гарантия iOS.
Основание: [W3C Audio Session, рабочий проект](https://www.w3.org/TR/audio-session/).

Версия 14: непостоянный LOGIN_REQUIRED/HTTP 403 от обоих клиентов вызывает
ровно один автоматический повтор через 600 ms. Проверены восстановление,
ограничение числа попыток и отказ без retry для UNPLAYABLE. Технические коды
остаются в отчёте, в интерфейсе нет ложного требования войти в аккаунт.
Это смягчение временных отказов, не решение всех ограничений облачного YouTube.

## Мобильный клиент, версия 13

Alex подтвердил нормальное YouTube video/audio воспроизведение после v12.
Основной адрес теперь открывает мобильный клиент, а прежний стенд сохранён
в `/lab`. Плеер, resolver, HLS relay и оригинальная AAC-LC дорожка общие.

Реализованы вкладки «Главная», Shorts, «Подписки», «Вы», поиск и подсказки,
продолжение выдачи в порядке API, экран просмотра и мини-плеер без пересоздания
media element. История с позицией, «Смотреть позже», liked, очередь и подписки
локальные, не синхронизируются с YouTube. Автопродолжение очереди включается
в настройках. SponsorBlock пропускает sponsor/selfpromo, недоступный сервис
не включает рекламный fallback. Добавлены скорость и PiP по доступности API.

Гостевая главная может быть пустой по решению YouTube. Вместо выдуманной
персонализации предлагаются поиск и темы. Google login, именованные плейлисты,
настоящие YouTube-загрузки, субтитры, расшифровка, девять нативных тем и полная
настройка SponsorBlock ещё не перенесены. Полная копия iOS не объявляется готовой.

Сборка без внешних зависимостей объединяет модули `worker/` в один Worker ESM.
Проверки: `node scripts/test.mjs`, `node scripts/test-catalog.mjs`,
`bash scripts/build.sh`, `node scripts/validate-artifact.mjs`.
Локальный сервер `node scripts/serve.mjs` нужен только разработчику, не PWA.

Версия 12: отчёт v11 подтверждает playing при rate=1, но Alex слышит ускорение.
В master проблемного ролика первой была арабская автодублированная HE-AAC
дорожка. Вместо выбора первой строки теперь выбирается original, затем DEFAULT,
затем недублированная дорожка. Внутри приоритета предпочтителен AAC-LC.
Аудио отдаётся через отдельный master с явным CODECS, а не голый media playlist.
Язык, название и кодек включены в отчёт без signed URL. Парсер quoted attributes,
выбор дорожки и Safari Range проверены адресными тестами. Это исправление
выбора источника, не доказательство устранения слышимого ускорения на iPhone.

Версия 11: отчёт v10 содержал только start-failed, time=0 и rate=1, то есть
ролик не запустился и скорость этим отчётом не проверена. Серверный запрос

Версия 10: Alex подтвердил запуск YouTube в v9 и сообщил об ускорении. Старый
отчёт не содержал playbackRate и закончился в начале ролика, поэтому причина
не доказана. Новые источники получают defaultPlaybackRate=playbackRate=1 и
сохранение высоты тона, скорость повторно инициализируется после metadata.
Ручное изменение скорости после старта не блокируется. Экран и отчёт показывают
фактическую скорость, событие ratechange регистрируется. Регрессионный тест
проверяет сброс унаследованных 2x и повторное применение после metadata.

Версия 9: отчёт v8 не содержит phone-proof-start; API уже вернул источник,
после чего запрос Safari bytes=0-1 к HLS получил HTTP 400. Исправлена обработка
Range для плейлистов: upstream читается полностью, ссылки переписываются,
затем диапазон применяется к итоговым UTF-8-байтам. 206/Content-Range/HEAD/416
проверены отдельно, диапазоны сегментов и MP4 по-прежнему передаются upstream.
Probe-playback теперь воспроизводит двухбайтовую проверку Safari до декодирования.
Это отдельное исправление relay, не заявление о решении всех ограничений YouTube.

Версия 8: экспериментальная аттестация на телефоне через
[BgUtils 4.0.3, MIT, LuanRT](https://github.com/LuanRT/BgUtils).
При PO_TOKEN_REQUIRED PWA запускает sandbox без allow-same-origin, запрашивает
проверку у Google и передаёт токен сайту POST-запросом для одного ролика.
Токен не хранится в localStorage, отчётах или query API-запроса. В медиассылке
он используется по протоколу CDN; серверные журналы не должны публиковаться.
Успешность аттестации и воспроизведения на iPhone пока не подтверждена.
Компьютер-сервер и туннели не используются и не являются допустимым fallback.

Цель, задачи, подзадачи и фактические статусы: [PLAN.md](PLAN.md).

Отдельный публичный инженерный прототип, не замена iOS-приложения.

- PWA manifest и service worker только для оболочки.
- Контрольный MP3 SoundHelix для проверки фонового звука отдельно от YouTube.
- Сохранение контрольного MP3 в IndexedDB и проигрывание Blob URL в авиарежиме.
- Собственный video/audio element, Media Session, журнал событий без media URL.
- YouTube: гонка IOS/VISIONOS, проверка video ID, HLS relay с проверкой HTTPS,
  доменов и каждого redirect. Range передаётся для перемотки. Нет iframe fallback.
- HLS нативно или hls.js 1.7.4 с jsDelivr. Это не полная блокировка рекламы
  Brave/Shields или перенос нативного механизма AxrTube. SponsorBlock пока нет.
- Нет аккаунтов, поиска, очереди, офлайн-скачивания YouTube или гарантии фона.
- Доступ публичный по просьбе владельца. Relay ограничен доменами Googlevideo,
  но не предназначен для массовой раздачи. Не записывать подписанные URL,
  cookies и токены в документы.

## Brave: подтверждённая граница

`4cceafa6ebd03ab0ed979e35c26e0ac948f3dffc`:
