# AxrTube PWA: цель и этапы

Цель: отдельный публичный клиент для iOS/Android с собственным медиаплеером,
воспроизведением без официального рекламного iframe и максимально доступным
на веб-платформе функционалом AxrTube. Нативное приложение не изменять.
Не обещать полное совпадение с AVFoundation и не скрывать ограничения YouTube.

## Принятые границы

- Только телефон и сайт. Mac/iMac как сервер, туннели, отдельные локальные
  token-сервисы и зависимость от включённого компьютера запрещены владельцем.
- Фоновый звук в проверенном сценарии принят; повторять MP3-тест не требуется.
- Браузерная аттестация Google остаётся экспериментом для отдельных отказов.
  Принятый YouTube playback не является подтверждением её использования.

- Сайт остаётся публичным по указанию Alex.
- Рекламный iframe не является fallback. Блокировка рекламы обязательна;
  SponsorBlock отдельный слой, его ещё нужно перенести.
- Нет автоматического удаления медиа, настроек и чужого dirty state.
- Нет секретов, cookies, signed media URL и персональных отчётов в репозитории.
- Каждый шаг: минимальная реальная проверка, публикация, адресный тест на телефоне.
- К следующему большому этапу переходить после проверки предыдущей границы.
- Не создавать серверную авторизацию или платные ресурсы без отдельной нужды.

## Приёмка v13

1. Адресные тесты каталога: порядок, дубликаты, исключение рекламы, continuation.
2. Старые тесты relay/resolver/player и новый тест позднего ответа после закрытия.
3. Мобильный браузер: поиск -> карточка -> watch -> сохранить -> мини-плеер -> «Вы».
4. Данные истории и «Смотреть позже» сохраняются после перезагрузки.
5. Одна публичная публикация; физическая приёмка оболочки на iPhone впереди.
6. Приёмка Android, standalone и офлайн не выводится из Safari playback.

## Текущая поправка v15: переход в фон

- Alex сообщил: после сворачивания пауза, ручной Play на Lock Screen продолжает
  длительное фоновое воспроизведение. Это отдельный дефект входа в фон.
- В обработчиках приложения нет прямого pause на visibilitychange/pagehide.
- Добавлены Audio Session playback и ограниченная попытка восстановления
  при паузе непосредственно после hidden-перехода. Ручная пауза приоритетна.
- Unit-проверка логики не заменяет iPhone. Приёмка: играющий ролик -> свернуть
  или заблокировать -> звук продолжается без нажатия Play на Lock Screen.
- Если Safari отвергнет попытку, отчёт содержит background-resume-blocked.
  Не обещать, что Web API снимает все ограничения фонового видео iOS.

### Уточнение v16 по реальному отчёту

## Проверка медиапути при его изменении

1. Не ограничиваться HTTP 200 resolver: получить manifest, media playlist и байты сегмента.
2. Проверить отдельно video и audio-only, без записи signed URL в вывод.
3. Минимальные targeted tests для затронутой границы; один deployment.
4. Alex запускает тот же YouTube-ролик, блокирует экран, проверяет минуту звука.
5. Зафиксировать manual pause отдельно от непроизвольной остановки.
6. Не помечать Android, PWA standalone, очередь или офлайн принятыми по Safari MP3.

## Текущие ограничения

Обязательные алгоритмы YouTube закрыты и могут менять ответы. Web background
не даёт гарантий нативной сессии AVAudioSession. Service worker не является
постоянным аудиосервисом. Brave использует нативный код, он не переносится
буквально в веб. Бесплатный публичный relay не предназначен для массовой раздачи.
