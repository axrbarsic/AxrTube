AXRTUBE PWA: НАЧАТЬ ЗДЕСЬ
Снимок опубликованной версии 38, экспорт от 12 ноября 2026.

1. ЧТО ЭТО И ЧТО ПРОСИТ ВЛАДЕЛЕЦ

AxrTube является неофициальным мобильным клиентом YouTube без рекламного
iframe. Основная версия здесь представляет собой PWA, frontend и серверный
Cloudflare Worker. Пользователь хочет разместить её на другом сервере и
продолжить разработку с другой моделью ИИ. Главная нерешённая проблема:
на установленном PWA на iPhone нажатие системной карточки воспроизведения
на заблокированном экране открывает ДРУГОЙ сохранённый веб-ярлык.

Язык общения с владельцем: русский. Писать понятно, он не программист.
Не использовать символы длинного и среднего тире. Не обещать исправление
до повторной проверки владельцем на физическом iPhone. Действовать по одному
ограниченному эксперименту, сохранять данные и не сбрасывать авторизацию.

Обязательное продуктовое ограничение: НЕ УДАЛЯТЬ блокировку рекламы.
Нельзя возвращать официальный рекламный iframe как тихий fallback.
Ошибка доступа к источнику должна оставаться явной ошибкой.
Приложение должно работать как телефон + публичный сайт/сервер. Компьютер
владельца не должен быть постоянным мостом, прокси или источником потока.

2. ПРОИСХОЖДЕНИЕ И СОСТАВ

Исходный сайт:
https://axrtube-pwa-playback-lab.axrbarsic.chatgpt.site/

Опубликованная версия: 38.
Точная серверная исходная ревизия:
ca7760136c856012e07b4b080ba0bd30f3e9187d

При экспорте получены заново исходники удалённого репозитория Sites;
ревизия сверена с сохранённой версией и публичным /api/version.
source/ содержит tracked-исходники этой ревизии, без .git и credentials.
source/dist/ содержит воспроизведённую сборку из этих исходников. Это не
побайтовый дамп закрытой инфраструктуры провайдера, а воспроизводимый Worker.
portable/ содержит добавленный для экспорта локальный Node-адаптер и проверки.
01_RUN_AND_MIGRATE.txt объясняет запуск и перенос.
02_ISSUES_AND_EXPERIMENTS.txt содержит подробный журнал известных проблем.
START_PROMPT.txt можно скопировать в новую сессию ИИ.
SHA256SUMS.json содержит контрольные суммы файлов комплекта.

НЕТ в архиве: серверных env secrets, Google Client Secret, ключа шифрования
cookies, refresh/access tokens, пользовательских cookies, локальной истории
телефона, загруженных пользователем медиа, Git credentials, полного sysdiagnose.
Это намеренно. Данные браузера невозможно перенести простым ZIP сайта.

3. БЫСТРЫЙ ВХОД В АРХИТЕКТУРУ

Основные модули в source/worker/:

index.js: Worker fetch router; HTML лаборатории; генерация engine.js;
получение потоков IOS/VISIONOS; HLS manifests/media relay; контрольный MP3;
/api/version, /phone-proof и доставка собственных JS/CSS.

app-shell.js: HTML и CSS основного мобильного интерфейса.
app-client.js: навигация, главная, поиск, канал, профиль, настройки, очередь,
локальная библиотека и действия карточек.
catalog.js: YouTube catalog, парсеры, подсказки, канал и SponsorBlock.
youtube-account.js: серверный Google Web OAuth, PKCE/state/origin checks,
шифрованные cookies, обновление доступа, подписки и API аккаунта.
personal-home.js: авторизованный YouTube home через TVHTML5 browse,
порядок/continuations из ответа, без воспроизведения закрытого алгоритма.
background-playback.js: ограниченное восстановление пауз при уходе в фон.
app-updates.js: bootstrap, проверка версий и Service Worker shell cache.
i18n.js: ru/en/es/uk/ht/jam, автоязык и ручной выбор.
transcript.js и transcript-ui.js: получение стенограммы и UI копирования.
media-diagnostics.js: ограниченный локальный журнал, системный контрольный
плеер и отдельный устанавливаемый диагностический ярлык AxrTube Check.

Важные маршруты:
  /                          основной продукт
  /lab                       старая лаборатория, не основной интерфейс
  /system-player             простой MP3 в исходной установленной PWA
  /pwa-identity-test/         отдельный ярлык AxrTube Check
  /api/version               текущая версия
  /api/catalog               каталог/поиск/канал
  /api/resolve               получение медиапотока
  /media и /audio-master     потоковый relay/HLS
  /api/account и дочерние    профиль/подписки/плейлисты/главная
  /oauth/google/*            начало входа/callback/logout

Не ориентироваться на весь исторический текст /lab как на текущие функции
продукта: лабораторные подписи местами остались от ранних этапов.
Изменения продукта отслеживать через source/CHANGELOG.md и фактический код.

4. РАНТАЙМ И ПЕРЕНОС

Это НЕ статический сайт. Загрузка одного index.html на обычный web hosting
не заменяет Worker API. Нужен fetch-compatible Worker runtime либо HTTP-адаптер
на сервере с Node.js. Локальный адаптер приложен, но production TLS, reverse
proxy, лимиты запросов, эксплуатация и секреты на новом сервере настраиваются
отдельно. Текущий сайт при экспорте не изменялся и не перепубликовывался.

КРИТИЧЕСКИЙ БЛОКЕР ПЕРЕНОСА: в source/worker/youtube-account.js в начале
жёстко задан accountOrigin старого сайта. Его надо осознанно заменить на
НОВЫЙ доверенный HTTPS origin и пересобрать Worker. Не отключать проверки
Origin, SameSite, PKCE, state или шифрование ради устранения Origin rejected.
accountOrigin используется также в AAD шифрования и redirect_uri OAuth.

Для Google-входа нужны собственный Web OAuth client, новый разрешённый
redirect URI <NEW_ORIGIN>/oauth/google/callback, серверный Client Secret
и новый случайный 32-byte cookie key в виде 64 lowercase hex символов.
Все env-переменные перечислены в source/.env.example, реальные значения
надо задавать только на сервере. Не просить владельца выкладывать их в чат.
Не пытаться скопировать старые браузерные сессии или использовать секрет
в frontend. При новом origin пользователь входит заново.

source/.openai/hosting.json содержит идентификатор ИСХОДНОГО Sites проекта,
а не настройки нового сервера. Не публиковать через него поверх оригинала.
Новый хостинг требует собственной конфигурации. Для Node этот файл не нужен,
для исходного npm run build его пока достаточно сохранить как метаданные.

5. СТАТУС ФУНКЦИЙ, БЕЗ МАРКЕТИНГОВЫХ ОБЕЩАНИЙ

Есть мобильная лента/поиск/каналы/подписки/закрепления, local lists/queue,
Google-вход, собственный HLS/file плеер, режим audio, SponsorBlock, стенограмма,
языки и проверки обновления shell. Но это не полная копия backend YouTube.

ВАЖНО: ранее в разговоре звучали рекламные заявления об офлайн-загрузке.
Полноценные YouTube offline downloads в PWA здесь НЕ доведены до parity с
нативным приложением. Надёжно выделенный локальный контроль в лаборатории
сохраняет небольшой MP3. Не выдавать его за готовый YouTube downloader.

Фоновое воспроизведение владелец подтверждал длительным прослушиванием.
Но проблема неверной иконки Now Playing остаётся, а возможность фона и PiP
зависит от браузера/ОС. Нельзя обещать 100% работу на всех телефонах.

PWA speed-регрессия ранее была: некоторые потоки играли ускоренно. После
предыдущих изменений владелец подтвердил нормальную скорость в video/audio.
Последние контрольные отчёты показывали rate=1. Это не гарантия всех кодеков.

Google-вход не должен требовать двух ручных авторизаций: в исходниках есть
единый серверный account/refresh путь. Однако Google может отозвать доступ;
OAuth-проект был в Testing, что может ограничивать срок refresh token.
Перевод consent screen в Production в этой работе не подтверждён.
Авторизация «однократно навечно» технически не гарантируется.

6. ПРИОРИТЕТ НОВОЙ СЕССИИ

Сначала прочитать 02_ISSUES_AND_EXPERIMENTS.txt. Не повторять уже проваленные
эксперименты в исходном виде. Изменение имени иконки и отдельный manifest ID
не считать доказанным лечением. Не утверждать, что generic com.apple.webapp
в логах само по себе доказывает ошибку WebKit.

Следующая ещё НЕ выполненная граница: минимальная PWA на ДРУГОМ origin,
без унаследованного root Service Worker/хранилища исходного сайта.
Новый сервер/домен как раз позволит её проверить. Нужен отдельный ярлык,
обычный MP3 и проверка на том же iPhone, без удаления «ОК» или других иконок.
Если сбой повторится, это ослабит гипотезу об окружении старого origin,
но всё ещё не даст JS доступа к внутреннему владельцу системной сцены.

Перед большим рефакторингом зафиксировать исходный результат и один
изменяемый фактор. Проверять не только отсутствие ошибок JS, но и фактический
возврат по карточке Lock Screen. Успешный desktop-тест не равен iPhone acceptance.

7. СВЯЗАННАЯ НАТИВНАЯ iOS-РАБОТА

Есть отдельный Swift/AVPlayer проект AxrTube. Он НЕ включён в этот PWA ZIP.
В последней нативной работе начат перенос навигации, профиля и списка каналов
из PWA; полная сборка/установка/визуальная приёмка не выполнены, так как телефон
был недоступен и на Mac было критически мало места. Нативный плеер, Keychain,
загрузки и Share Extension нельзя подменять PWA-кодом без отдельного решения.
Не обещать, что этот ZIP содержит последние Swift-изменения.

8. КАК ОТЧИТЫВАТЬСЯ

Писать отдельно: что изменено; какие адресные тесты реально прошли; где
проверено воспроизведение; что ответил владелец; что ещё не установлено.
Не называть «исправленным» отрицательный пользовательский результат.
Не выгружать системные архивы, cookies, signed media URL и токены публично.
