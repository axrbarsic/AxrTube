# AxrTube: исполнительная сессия

## Роль
- Эта проектная сессия является исполнителем AxrTube, а не командным
  центром. Она самостоятельно исследует код, исправляет проект, собирает,
  подписывает, устанавливает и проверяет приложение на физическом iPhone.
- Командный центр формулирует checkpoint и принимает результат; продуктовую
  работу выполняет эта сессия.

## Текущий контракт
- Работать в текущем исходном дереве AxrTube; готовые IPA и сторонние
  серверы/сайдлоадеры не использовать.
- Сохранить background audio, воспроизведение при блокировке, Lock Screen
  controls, Picture in Picture, Audio Only, загрузки и Share Extension.
- Подпись, Bundle ID, App Groups, entitlements и extensions привести к одному
  согласованному локальному набору для Apple Developer Team Alex.
- Если Firebase мешает личной сборке, убрать только обязательность Firebase,
  не ломая основные функции.
- Не коммитить и не публиковать Apple ID, Team ID, UDID, сертификаты, профили,
  секреты и приватные конфиги.

## Коммиты и push (правило по умолчанию)
- Каждый завершённый и проверенный checkpoint (сборка/тесты/установка зелёные)
  коммитить с осмысленным описанием и пушить в origin (ветка alex-personal) сразу
  по завершении, без отдельной команды.
- Перед commit: `git status`/`git diff` — стейджить только относящиеся к фиче
  файлы; локальные эксперименты и логи инструментов
  (`.codex-yandex-poc/`, `.playwright-cli/`) держать в .gitignore, не коммитить.
- Сообщение коммита — краткое, в стиле репо (например, «Tune AxrTube parallel
  audio download for weak networks»), без раскрытия секретов и личных
  идентификаторов. После push обновлять README/CHANGELOG по факту.
- Не расширять scope и не вносить косметические либо несвязанные изменения.

## Исполнение и проверка
- Сначала изучить README, структуру targets/extensions, зависимости, signing и
  текущее состояние Xcode; затем исправлять конкретные блокеры по одному.
- Экономить сборки: не повторять зелёные шаги без изменения кода. Перед тяжёлой
  сборкой запускать `~/.codex/tools/disk_guard.sh --force`.
- Финальная проверка — signed build, установка поверх приложения на основной
  физический iPhone, запуск без краша и адресная проверка YouTube playback,
  background/locked-screen audio, Lock Screen controls и PiP.
- Останавливаться только на действительно необходимом физическом действии Alex
  и давать ему одно короткое точное указание. После ответа продолжать с того же
  места.
- В отчёте перечислить изменения, результат сборки/установки, проверенные
  функции, точные оставшиеся ограничения и строку `Диск:`.

## Публичная документация
- Каждый завершённый пользовательски видимый checkpoint синхронизировать с
  публичным состоянием проекта: обновлять README и CHANGELOG по факту, а
  GitHub description/topics — только когда прежняя формулировка стала неполной
  или неточной. Не обещать непроверенные функции. После push выполнять
  публичный read-back README, description и topics.
