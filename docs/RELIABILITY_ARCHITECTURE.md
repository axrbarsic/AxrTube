# Архитектура надёжности AxrTube

## Цель и границы

Актуализация 9 сентября: исправления таймлайна, переключения офлайн-роликов, сеток и полных заголовков компактных карточек вошли в подписанную сборку, установленную по USB и запущенную на iPhone. 14 адресных тестов прошли, после последних защит повторены 4 теста таймлайна, включая A → B → перемотку на 20-ю секунду. Физический визуальный вердикт ожидается. Описанные ниже проверки от 8 сентября являются историей этапов, а не указанием, что эти правки всё ещё отсутствуют на устройстве.

Результат важнее происхождения кода. Brave является одним из изученных примеров, не обязательной архитектурой. Совместимость локальной медиатеки, стенограмм, аккаунта и настроек сохраняется при замене внутренних компонентов.

Полная миграция не объявляется завершённой по одной сборке. Каждый слой получает отдельную проверяемую границу и тесты последовательностей, затем подключается к реальному приложению.

## Обязательные правила

1. Сохранение ролика не зависит от того, какой ролик выбран для воспроизведения.
2. Принятая заявка немедленно записывается в медиатеку. Ошибка не удаляет запись.
3. Отмена адресуется ID загрузки, не абстрактной «текущей задаче».
4. Ответ предыдущей задачи не может завершить или изменить новую задачу с тем же ID.
5. Очередью управляет сервис, экран лишь отображает состояние и отправляет команды.
6. Прерывание звука блокирует транспорт, а не только громкость. Запоздалое восстановление не может обойти прерывание или ручную паузу.
7. Устойчивое состояние плеера не останавливает загрузки других роликов. Временный приоритет буфера не превращается в бесконечное зависание очереди.
8. Смена контейнера iOS не означает потерю файла. Ремонт записи не удаляет медиа и не использует сеть.
9. YouTube-реклама не допускается в пользовательском playback-пути. Существующая блокировка и SponsorBlock сохраняются; ошибка источника не должна автоматически включать рекламный embedded player. Вечная совместимость с будущими изменениями YouTube не обещается, обход DRM не добавляется.

## Слои

| Слой | Ответственность | Не должен делать |
| --- | --- | --- |
| Интерфейс | Команды с точным ID, отображение состояния | Управлять продвижением очереди, владеть аудиосессией |
| Координатор загрузок | Очередь, версии заявок, повторы и отмена | Знать детали URLSession callbacks или состояние выбранной карточки |
| Транспорт | Фоновые HLS/файловые задачи и проверка ответов | Удалять записи медиатеки, выбирать следующий ролик |
| Хранилище | Атомарные записи, локальные пути, безопасная сверка | Запускать плеер или сеть |
| Владелец воспроизведения | Намерение пользователя, прерывания, текущий item | Владеть очередью скачивания |
| Проверки | Реальные границы команд, перестановки событий, сбои | Подменять физический звук значением rate или движением осциллографа |

## Порядок миграции

- [x] Отделить координатор загрузок от транспорта и сделать зависимости подставляемыми в тестах.
- [x] Проверить быстрые команды A/B, отмену, восстановление и поздние callbacks.
- [x] Подключить асинхронные загрузчики, смену качества и recovery к единой границе разрешения воспроизведения.
- [x] Ограничить приоритет буфера тремя секундами непрерывного ожидания. Повтор одного ролика больше не удерживает очередь остальных.
- [ ] Проверить публичные экраны и настройки на устаревшие владельцы состояния.
- [x] Провести одну независимую проверку и signed iOS build.
- [ ] Получить физическую приёмку звука, очереди и фонового режима.

Остающиеся крупные зоны старой архитектуры: выбор источников и fallback, смена качества, lifecycle полноэкранного/встроенного плеера, кэш стенограммы. Их нельзя считать переписанными, пока маршруты не переведены и не проверены.

Отдельные незакрытые контракты: `downloadsWiFiOnly` пока не влияет на нативные передачи; экономичная первая копия и улучшение качества не реализованы; восстановление HLS ограничено системной сессией Apple. Эти пункты не являются обещанием уже работающей функции.

## Проверка первого этапа, 8 сентября 2026

Проверяется настоящий VideoDownloadService с управляемым транспортом и resolver, включая сохранение и финализацию через настоящий DownloadStore. Это не тест отдельной копии алгоритма. Проверка аудио вызывает производственную границу PlaybackViewModel и обработчик готовности качества.

Одна независимая проверка завершена. По её замечаниям восстановленные задачи используют актуальный лимит общего SettingsStore, а отклонённый stall recovery не возвращает ложное `isPlaying=true`. После исправлений 8 тестов координатора и 4 теста владельца воспроизведения прошли. Подписанная сборка iOS прошла; она проверяет компиляцию реальных UIKit/AVAudioSession путей, отсутствующих в macOS-тестах.

## Исправление локального таймлайна, 8 сентября 2026

На физическом интерфейсе первого этапа карточка локального видео оставалась на `0:00` с неизвестной длительностью и без живого сигнала. В свежем журнале `AVPlayer` уже находился в состоянии воспроизведения. Это доказало расхождение состояния транспорта и интерфейса, но не подтверждало слышимость звука.

Причина состояла из двух частей: локальная ветка загрузки не публиковала длительность item, а `WaveformFrameDriver` обнулял позицию и не запускал визуализацию без положительной длительности. Наблюдение перенесено к `player.currentItem` и действует для всех источников. Поздний результат проверяет идентичность установленного item; остановленный скрытый плеер не публикует Now Playing заново. Дублированные обработчики длительности удалены из веток выбора источника.

UI использует измеренную позицию AVPlayer, не самостоятельно экстраполированное время. Неизвестная длительность не обнуляет уже известную позицию и не запрещает чтение PCM-сигнала.

| Проверка дополнительной правки | Результат |
| --- | --- |
| Item timeline, playback authority, background policy | 8 тестов, 3 группы, PASS |
| Независимая проверка новой границы | PASS |
| Одна simulator-сборка | BUILD SUCCEEDED |
| iPhone 17 Pro Max Simulator, локальный MP4 без длительности в записи | Длительность `1:00` получена из файла, позиция продвигалась, PCM-сигнал видим, fullscreen не открыт |
| Физический iPhone | Не подключался после указания пользователя; новая правка не установлена |

Тестовый ролик удалён только из созданной для проверки записи симулятора, остальные данные сохранены. Приведённый выше hash относится к первой установленной сборке, а не к дополнительной правке таймлайна. Исправление не является полной физической приёмкой фонового звука.

Веб-компоненты получения ссылок изолированы от воспроизведения системным WebKit API. Разрешён только manifest основного videoDetails.videoId, совпадающего с запросом. Рекламные карточки фильтруются существующим catalog parser, SponsorBlock сохранён. Неизвестный DOM media URL не используется как fallback. Это не гарантия распознавания любых будущих серверных рекламных вставок YouTube.

Свежий журнал физического iPhone показывает обработку прерываний и успешную реактивацию сессии. Запись transportHealthy в старой диагностике подтверждает лишь состояние AVPlayer, не слышимость звука. Физическая приёмка нового аудиопути обязательна; её нельзя заменить движением таймлайна или осциллографа.

Официальная системная граница: [Apple, приостановка медиа в WKWebView](https://developer.apple.com/documentation/webkit/wkwebview/setallmediaplaybacksuspended(_:completionhandler:)), [Apple, аудиопрерывания](https://developer.apple.com/documentation/AVFAudio/handling-audio-interruptions).
